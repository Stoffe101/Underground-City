## C. One command: `gradlew runClient` with the complete development pack

**Can a normal user launch the complete pack with one Gradle command? Yes on the platform that was tested, with two honest caveats: it has been run on Linux in the cloud and on GitHub's hosted Linux runner, not on Windows 11 and not from IntelliJ IDEA, because no such machine is available to the cloud session.** The Windows path is the same Gradle build (`gradlew.bat`, no shell scripts, no hard-coded paths), but it is unverified. [dev-client.md](../technical/dev-client.md) is the full guide.

| Question | Answer |
| --- | --- |
| Java | **JDK 17** (the build asks for a 17 toolchain and does not download one). IntelliJ: Gradle JVM = 17 |
| One-time setup | none; open the repository root as a Gradle project (IntelliJ) or use a terminal there |
| The command | `.\gradlew.bat runClient` (Windows) or `./gradlew runClient`; IntelliJ: the shared configuration **"Underground City - runClient (full dev pack)"** from `.run/` |
| What it loads | Minecraft 1.20.1, Forge 47.4.10, Underground City Core, Q Shop 1.8.4, The Lost Cities, TaCZ 1.1.8-hotfix2, TaCZ Blueprints 0.1.3, Modern Life 1.75, Immersive Vehicles 24.0.0, the Official Content Pack V29 and the Official Automobile Pack V3, plus the original three-city world package and the Lost Cities profile that selects it |
| What is downloaded | about 170 MB of mods from the original authors' pages (Modrinth Maven, Q Shop's GitHub release), each verified against a pinned SHA-512 / SHA-256 before use; a mismatch stops the build with the file name. Minecraft and Forge are prepared by ForgeGradle the first time (several minutes). Nothing third-party is committed |
| Game directory | `rpg-core/run-dev/` (mods, configuration, options, logs, screenshots) |
| World | `rpg-core/run-dev/saves/UC-Dev-5908`, seed 5908, created on the first launch and reopened afterwards; it is never overwritten, and other worlds are untouched. The first start also builds Founders Row near the spawn (see section H) |
| First screen | the first-login registration screen (city, then profession); until you confirm, the supply and employer counters will not talk to you |
| Dedicated server | `.\gradlew.bat runServer -PucAcceptEula=true` (same pack, same seed, `rpg-core/run-dev/world`); the flag is your acceptance of the Minecraft EULA |
| A different pack | `-PucPack=none` (Core only), `-PucPack=firearms,vehicles` and so on; `-PucAutoWorld=false` to stay on the title screen; `-PucUsername=Alice` for a second developer |
| Reopening an existing dev world | Minecraft asks "Worlds using Experimental Settings are not supported" because a mod-registered generator is not vanilla-stable; the launcher answers *Proceed* for its own development world |

What was fixed to make this possible: a committed Gradle wrapper (8.14.3, checksum pinned; the validator and the hosted wrapper-validation job accept exactly that jar), a root build that forwards to `rpg-core`, Modern Life's configuration read (`-Dproduction=true`, because Forge only throws when `FMLEnvironment.production` is false), Immersive Vehicles' content packs (they are found by scanning the game directory's `mods` folder, so the manifest places them there), the Lost Cities profile and the Q Shop currency templates (staged only when absent), and the ignored-directory bug that hid the generated world package from the first hosted run (`.gitignore` matched `run-*/`).

**Evidence.** `./gradlew runClient -PucLaunchSmoke=true` in the cloud container: nine mods with versions, 470 and 137 content-pack items, seed 5908, an Operations Terminal opens its screen. The same command on a GitHub-hosted runner under Xvfb with software OpenGL (`dev-client-smoke.yml`, job "runClient launches the complete pack and reaches a terminal", about 4 minutes from a cold cache): `[UC-LAUNCH] RESULT pass`. `./gradlew runServer -PucBootSmoke=true` boots the same pack (hosted job "runServer boots the complete pack"). **Not covered:** Windows, IntelliJ's own Gradle import, a real GPU, two players on this pack, and driving or sailing (section E).

The first hosted attempt failed, and the hosted log is why this is believable rather than assumed: the generated world package directory was named `run-config`, which `.gitignore` (`run-*/`) silently ignored, so the CI checkout had no Lost Cities configuration; it is now `game-config` and the diagnostic step prints Gradle's reason into the job log.
