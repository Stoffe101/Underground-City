# Risk register

Severity: critical/high/medium. The mitigation is a plan, not a claim of completion.

| Risk | Severity | Mitigation / evidence required |
| --- | --- | --- |
| Cross-mod incompatibility and dedicated-server crash | Critical | Minimal binary-search mod staging; pin versions; archive client/server logs and manifest |
| Existing city maps are incompatible or legally unsuitable | Critical | Permission register; export in disposable test worlds; run world validation; preserve originals |
| Generated city profile changed after chunks exist | High | Lock profile before first generation; back up then new world/region when modifying |
| Too many NPC pathfinding entities degrade TPS | High | Spatial budgets, activation and off-screen simulation; benchmark at target counts |
| Economy inflates due to infinite NPC purchases or loot duplication | High | Quantity budgets, demand curves, shared vs personalized sources, transaction audit |
| Taxes punish players for not logging in | High | Active-play counter; caps and grace periods; no real-time offline accumulation |
| Profession progression becomes grindy or impossible with 2 players | High | Task-based XP, NPC alternatives, reachability graph/recipe validator |
| Firearm systems break combat balance or policing | High | Tier, rarity, ammo cost, NPC accuracy, cover, legal rules, controlled encounters |
| Saved contracts/roles/skills corrupt on update | Critical | Versioned save schemas, migrations, idempotency, backup/restore tests |
| City and quest triggers rely on fixed coordinates | High | World-data registry with region and location identifiers, configurable bindings |
| Overengineering delays any playable result | High | Small P0.1 scope, phase gates, feature flags, deferral discipline |
| ARR project accidentally republishes third-party files | Critical | No binaries in git, asset ledger, notice review and build artifact policy |
| Two-player conflicting choices stall the main quest | Medium | Shared milestones plus individual choice state and explicit co-op conflict handling |

Review at each milestone; raise new risks when technical spikes reveal them.
| A Crew bank file is lost, corrupted or from a newer schema, so credits that left wallets are unreachable | High | One atomic fsynced file per world (`data/underground_city_crews.dat`); a failed write faults the ledger and refuses everything until restart; an unreadable file is reported on the Crew screen while solo play continues; back up the whole world (the playtest guide says so); `/uc_crew pending` and `resolve` for an operator. Not tested: a hand-corrupted file on a hosted run |
| A transfer is interrupted in a way recovery cannot decide (a wallet value matching neither recorded value) | Medium | Recovery only reads the wallet; such a transfer is logged, blocks only that player, and needs an operator's `/uc_crew resolve <uuid> true` or `false`; the journey exercised the two decidable cases with a real process halt, not this one |
| Crew rules are misread as shared money everywhere (Q Shop's own shop screens always spend the personal wallet) | Medium | The Rules page now says so beside the finance mode, and the purchase history names the bank's share; shared finances cover work-order pay and exchange purchases only; revisit if Q Shop gains an account API. A player who buys in a Q Shop screen with an empty wallet is simply refused by Q Shop |
| A leased home can be griefed from a way the guard does not cover | Medium | **Reduced (D-090).** Pistons, hoppers and droppers across the shell, modded containers (recognised by their item handler, not only the vanilla interface), item frames, armor stands, paintings and chest vehicles, placed entities, buckets, fire, mob griefing, hostile spawns, trampling and explosion victims are now covered, each with a GameTest and a control (the same action outside a home still works) and each shown to fail when the check is switched off. **Still open:** fire that spreads in from outside a home, lightning, fluid dispensers, vehicles of mods other than the vanilla `chest_boat`, and any mod that moves blocks with its own code instead of a piston. The shell belongs to the city; creative mode is never held back; a house nobody leased is deliberately open (NPC burglary) |
| The opt-in survival set interacts badly with Lost Cities, vehicles and the other mods in a long session | Medium | Boot and GameTest records only; opt-in; add a played session before any default |
| A third-party table recipe makes a contract undeliverable (for example TaCZ fits a stock to the M4A1) | Medium | The firearm-contract GameTest checks that every gun requirement lists a gun the table builds plain; the item-source audit covers Core's own data |
| **A Crew-funded purchase moved the bank's credits into the buyer's wallet before the purchase was known to succeed, so a refused purchase left the member with the Crew's money (found in review; critical)** | Critical -> closed | **Fixed (D-089).** The bank's share is now a durable hold that never enters a wallet and is spent only when the work-order ledger's prepared purchase record names it (the single commit point). Regression test written before the fix and shown to fail on the old code; nine deliberate mutations are each caught; a crash at every boundary, an exception at every step, duplicates, two members and 220 random operations conserve every credit. **Not covered:** two clients on separate threads (the server thread serialises them; the tests interleave requests) and a power cut. See [crew-economy.md](../technical/crew-economy.md#4b-purchases-paid-from-the-bank-d-089-one-decision-never-through-the-wallet) |
| Offline-mode servers let anyone become any Crew member by typing a name | Critical when exposed, none on a closed network | **Mitigated (D-090).** The production-style server pack is `online-mode=true`, `enforce-secure-profile=true`, white-listed; a real server demanding an Encryption Request is checked by `scripts/run_auth_check.py`; the server logs a warning and tells each Crew member at login when it does not verify accounts. The two-client scripted journeys and the developer launch stay offline (their clients have no accounts) and are labelled so. **Not tested:** a successful login by a real Microsoft account. **No migration** from offline UUIDs exists or is silent: a world played offline stays on its trusted network or is restarted fresh ([identity.md](../technical/identity.md)) |
| A Crew bank hold is left unresolved after a crash and blocks the Crew | Medium | Holds are decided at server start, at login and at the start of every purchase from the work-order ledger (released when no prepared record names them); a Crew cannot be disbanded or left while one exists, and `/uc_crew pending` lists them. An operator's `/uc_crew resolve` covers wallet-value mismatches, not holds, because a hold is always decidable from the ledgers |
| The survival goods make the economy trivial or leave a trip impossible to prepare for | Medium | Finite shared stock with active-play refill at every outlet; provisions desks at wayside shelters with their own, smaller lines; prices are first guesses set against Q Shop's starter shop (a wayside loaf is 7 credits against the starter shop's 5, so the road costs a little more than the city; checked by `tests/test_survival_supply.py`); **no playtest has checked the balance against what a career earns in half an hour**. No medical item exists yet (no mod chosen) |
| A shelter built before the provisions desk was added has no desk | Low | Shelters placed by the development launch before this change keep their layout until `/uc_district undo` and a rebuild; the desk is part of both shelter designs now (GameTest `theProvisionsDeskIsPartOfBothShelterDesigns`) |
| Everything passed in isolated sets or scripts but the full pack with a real session has never been played | High | The combined journey (generated Lost Cities world, every pack set, two real clients, abrupt server death, restart) removes the "only isolated sets" gap for the code paths it drives; **no person has played**. The Windows playtest guide is the first human test and records what to report |
| **Lost Cities stalls the server thread for seconds to more than a minute after bulk chunk generation in a city** (a 75.8 s tick seen on a hosted run; the watchdog kills a server at 60 s) | High | **Root-caused and reproduced, not fixed upstream (D-096).** Cause and numbers in [lost-cities-stalls.md](../technical/lost-cities-stalls.md): the mod's world-tick task (`GlobalTodo`) finishes generated buildings on the server thread. Pregenerating in a city region needs pacing (`StallProbe` shows the effect of a paced request) and the production watchdog stays on; a draft upstream report is in the document and is **not posted** without the owner's approval |
| A mod writes its own configuration while Forge reads it, so a first start fails or a file is corrected (seen once in eight starts of Traveler's Backpack, which is retired) | High | **Measured for the replacement (D-097).** [first-start-stability.md](../technical/first-start-stability.md) records repeated clean first starts and populated restarts of Sophisticated Backpacks + Core on a production-style server, with and without the generated configuration pre-seeded; the journey runner keeps its (empty) list of tolerated first-start races and counts any config correction |
| The backpack's server paths bypass the home guard (an inventory-interaction packet with a client-chosen position; a placed pack's Feeding upgrade feeding bystanders) | High -> reduced | **Closed by two pseudo mixins with failing-without-them tests (D-093).** If the mod changes those classes the mixins silently do nothing (`required: false`), but the two GameTests fail, so a mod update that breaks the gate is visible at the next hosted run. Known limit: a placed pack's magnet collects dropped items within three blocks across a thin wall |
| An older world that holds Traveler's Backpack items loses them when the mod is no longer installed | High | **Documented, not automatic.** [backpack-migration.md](../technical/backpack-migration.md) records what Forge actually did in an experiment and how to keep the items (load the `legacy_travelers` set once, move the contents out, then switch). Nothing converts items; nothing deletes them silently |
| Removing monsters leaves a recipe or progression step with no source (gunpowder, string, ender pearls, blaze rods, spider eyes) | High | Every root has a route or a stated exclusion; `ProgressionAuditGameTests`, `scripts/audit_item_sources.py` and the jar scan fail when a mod update adds a new dependency on a hostile drop (D-095). Prices and stock of the routes are guesses |
| Players read "no monsters" as "no danger", or the world feels empty at night | Medium | Hunger, thirst, falls, fire, drowning and people (guards, criminals) remain; the profile is a one-line switch (`CLASSIC`). Only a played night can answer the feel; it is on the Windows playtest list |
