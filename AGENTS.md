# Agent / automation instructions

Project: Underground City, a private-play semi-modern Minecraft living-world RPG. Read `README.md`, `docs/README.md`, `docs/production/decisions.md`, and `docs/production/mvp-v0.1.md` before modifying code, world assets, or gameplay data.

- **GUI coverage and artifact hygiene**: Any integrated UI or panel must have a real-client capture case, matching `content/qa/gui-coverage.json`. Run `.github/workflows/visual-qa.yml` after GUI changes; inspect actual screenshots at 1080p GUI 3 and 1440p GUI 2 for clipping/overlap/visual hierarchy/focus; fix and capture again. The CI's technical image check does NOT count as artistic approval. After review, remove `uc-visual-gallery-*` artifacts for that run with the reviewed-cleanup workflow, never before inspection. Uninstalled external mod GUIs are not covered. See `docs/technical/visual-qa.md`.
- **Live work orders**: Q Shop 1.8.4 is the sole credits provider. WorkOrderLedger uses fsynced prepared inventory/wallet/XP targets; never bypass recovery or client/server authorization. Work-order definitions live in vanilla datapack resources, accepted terms are snapshotted, employer demand is shared and advances only with human players. Preserve named/damaged/NBT gear. See docs/technical/economy-integration.md.
- **Named supplier**: reuse vanilla villager AI, preserve its saved UUID/dimension/PC binding and intercept emerald trading only for the registered clerk. No automated population/guard claims.
- **First playable supplier integration**: Q Shop 1.8.4 is the pinned wallet for the tested starter slice; broader pack compatibility remains under review. `TerminalNetwork` may open only hardcoded `uc_starter_supply` for registered citizens within 8 blocks of a real placed Operations Terminal, and only when Q Shop installed. Keep the shop civilian/vanilla only. Never accept arbitrary shop IDs, pricing or item IDs from the client. Original Q Shop templates in `content/integrations/qshop` must not overwrite real saves. See `docs/production/oct19-test-readiness.md`.
- **PC terminal source vs reality**: terminal-and-underworld is prototype design and a Python-only transactional model. Physical boxes require validated world markers, item NBT preservation, escrow, ownership and server-side authorization; shipment timeouts pause while owner offline. Never call simulations real in-game raids, chest contents, buyers, police, or interactive terminal. See docs/design/terminal-and-underworld.md.
- **Recurring procurement (hard design rule)**: one-time trips are not enough; advanced jobs repeatedly consume specialist materials unique to the three production cities. Keep common vanilla materials ungated; use limited shared merchant stock, travel permits and shipment/convoy routes so 2 players can batch errands. Live today: nine original Core commodities, shared finite stock per city, active-time replenishment, durable idempotent purchases through the same prepared-settlement journal as deliveries, twelve recurring orders with a 1.3x-2.1x credit margin guard. Generated from `content/gameplay/regional-content.json`; edit the source and run `scripts/generate_regional_content.py`. Never accept prices, stock, city or item IDs from a client, never claim the geographic gate proves road travel, and never claim the Python `simulate_regional_supply.py` is live trading. See docs/design/recurring-supply-chains.md and docs/technical/economy-integration.md.
- **Inter-city progression and burglary**: All advanced careers need real rival-city journeys and accessible nonviolent supplier routes. A "visit" is currently a server-recorded use of a placed terminal inside a data-defined city circle; native Lost Cities highways do not connect the fixed cities; Core's own corridor road feature builds two highways with bridges into NEW chunks only (water between the cities is intended: bridge or boat) and each change needs a block survey plus review of the real bridge frames. The Household Safe (`underground_city:property_cache`) is the only real property container: operator-registered, shared stock, lockpick-forced, survival-unbreakable, restocked lazily in active time. It is not placed in generated buildings and has no NPC funding, witnesses or police. See docs/design/intercity-progression.md and docs/design/gradual-property-restock.md.
- **World prototype safety**: The three-city generator is experimental, creates original Lost Cities data, and is not a world save; never describe procedural skylines as furnished inhabited cities or unassigned loot tables as loot actively placed in buildings. Measured fact: the planner's highway hubs ignore predefined cities, so the fixed-city profile has no native highways; roads come from the `corridor_roads` feature, which must never be pointed at an existing save. Read the real frames, not just the pass/fail image check. See docs/technical/three-city-prototype.md.
- **Onboarding provider screening**: generate candidates only from the pinned content/modpacks/onboarding-candidates.json registry; no third-party JARs in commits/artifacts; headless Forge GameTest is not client UI proof. See docs/technical/onboarding-screening-packs.md.
- **Reuse before rebuilding**: evaluate installed compatible mods, creator-approved configs, and existing modpack components before writing replacement systems; document choice and APIs. See `docs/technical/reuse-first.md`.
- **Do not silently lock technologies**: Java 1.20.1 / Forge 47.x / Java 17 are candidate baselines. Verify exact versions and dependencies before implementation.
- **No unlicensed imports**: Never copy external mod binaries, structures, music, textures, screenshots, scripts, or maps into this repo without explicit applicable permission; update the third-party register.
- **NPC-first co-op**: All essential story quests and professions must be completable with two players and NPC substitutes.
- **Server-authoritative systems**: Money, inventory rewards, tax, reputation, crimes, faction control, and XP are validated server-side and saved durably.
- **Data-driven gameplay**: Stable namespaced IDs; schemas for careers, recipes, cities, contracts, items, and loot; no hardcoded world coordinates.
- **Preserve worlds**: Backup before editing/generated terrain, test migration, never overwrite a user's live save.
- **Avoid incoherent simulation**: Only NPCs near players require full entity behavior; off-screen activity is simulated deterministically and bounded.
- **Quality evidence**: Run lint/smoke tests; verify multiplayer and persistence; manually inspect screenshots for UI/UX. Never claim a tested result without a recorded test.
- **Code hygiene**: Small reviewable commits, change logs for major decisions, no warnings hidden, no credentials or binaries committed.
- **Progressive deliverables**: Focus on the smallest complete slice first; never replace functional gameplay with speculative systems for scale.

- **No Create (owner direction, October 18, 2026; D-080)**: never add the Create mod, its add-ons, or any mod that hard-depends on it, as a dependency, candidate, recipe target or item-rebinding example. If a candidate's metadata lists Create as a *required* dependency, reject it and record why. Older mentions are superseded.
- **Five careers**: Farmer, Vintner, Smith/Engineer, Gunsmith/Arms Dealer, Hacker/Technician. Farmer and Vintner are two careers (D-067); any "Farmer/Vintner" as one career is outdated text. Each has a legal and an underground path on the same character.
- **Crews and shared money (D-081 to D-084)**: the Crew (membership, roles, invitations, bank, homes) is owned by Core's `CrewLedger` (`data/underground_city_crews.dat`, atomic and fsynced). Q Shop stays the only currency provider; the Crew bank is a Core escrow of Q Shop credits and every movement follows the wallet-first protocol in `docs/technical/crew-economy.md` (prepare record, wallet, verified player save, settle, recovery by comparing the wallet with the recorded before/after). Never accept an amount, role, permission or target from a client without server validation, never move money without a transaction id, never write a second wallet, and do not describe shared finances beyond what that document says is tested. Open Parties and Claims and FTB Teams were evaluated and are not the authority (reasons in the document); Lightman's Currency is a reference only.
- **Residences**: a residence is a registered region with an explicit owner (a player or a Crew), protected by `ResidenceGuard` (break, place, doors, containers, workstations, explosions). Joining a Crew never transfers a personal home; disbanding moves Crew homes to the founder, never to nobody. Unowned units are not free: they are leased from the ledger for credits and are finite.
- **Simulation world, no ordinary monsters (owner direction, October 19, 2026; D-094)**: Underground City is a modern-life simulation, not a monster-survival pack. Core's `SimulationWorld` refuses every hostile creature (an `Enemy` or the MONSTER category, of any mod) unless it is permitted (the tag `uc_permitted_hostile`, the data tag `underground_city:permitted_hostiles`, or an operator's deliberate spawn). The game is **not** put on Peaceful and `doMobSpawning` is **not** switched off. The default lives in code, so every launch is the same; `hostileMobs = "CLASSIC"` in `world/serverconfig/underground_city-server.toml` is the documented opt-in. Scripted enemies (guards, armed criminals, future raids) must call `SimulationWorld.permit(entity)` before they join a level. Do not add a recipe, order, route or reward that needs a hostile creature's drop without a route in `progression/monster_resources.json` (D-095); `ProgressionAuditGameTests` and `scripts/audit_item_sources.py` fail otherwise.
- **One backpack provider: Sophisticated Backpacks + Sophisticated Core (D-092, D-093)**: both are **All Rights Reserved**. Never commit, repackage or redistribute either jar; they are runtime-only, hash-pinned downloads in `content/modpacks/dev-pack.json` (set `survival`). Traveler's Backpack is retired (set `legacy_travelers`, only to open an old world once) and is never loaded together with Sophisticated Backpacks. The tier sizes, the 16 enabled and 55 disabled items and the server settings are generated from `content/gameplay/backpack-policy.json` by `scripts/generate_backpack_config.py` (`--check` in CI); change the policy file, never the generated files. A placed backpack is a container: `ResidenceGuard` and `BackpackGate` apply the Crew's storage rules to it. Nothing converts Traveler's Backpack items automatically (see `docs/technical/backpack-migration.md`); never delete a player's items to "migrate" them.
- **The server watchdog is never disabled to pass a test (D-096)**: `max-tick-time=-1` is allowed only on a disposable test server that exists to measure or to carry a fixture, and the document that uses it says so. Lost Cities can hold the server thread for seconds after bulk chunk generation (`docs/technical/lost-cities-stalls.md`); do not pregenerate a Lost Cities area in bulk on a production server.

Original project materials are proprietary and all rights reserved. Third-party material is independently licensed.

- **Cloud client journey fixtures**: `ucJourneyClient`/`ucJourneyPhase` are opt-in developer flags restricted to disposable `run-journey-*` directories. Never enable them in a valued world. `scripts/run_cloud_journey.py` rejects existing instances, uses loopback-only synthetic offline clients and uploads diagnostics/reports, never saves or third-party binaries.
- **Recorded screenshot reviews**: `content/qa/reviewed-runs.json` may list only artifacts actually downloaded and inspected. Cleanup validates exact IDs, gallery-only names and source SHA before deleting; preserve build/diagnostic artifacts.

- **Native world visual fixtures**: `ucWorldTour` loads only a disposable `run-world-tour/saves/world` clone and captures actual city environments. Do not substitute diagrams for terrain evidence. World/gallery artifacts retain one day; review each actual image before exact-ID cleanup.
- **Local cloud verification**: the Claude cloud container can build Core, run dedicated GameTests, run the native client under Xvfb with software OpenGL and run Lost Cities from Modrinth Maven for research (never committed). Prefer reproducing a hosted failure locally before iterating in CI. When artifact downloads are blocked, hosted workflows print review copies into job logs (`scripts/emit_review_images.py`); say exactly what you viewed.
